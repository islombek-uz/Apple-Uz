Git & GitHub

5 nafar dasturchi uchun jamoaviy loyihada ishlash bo'yicha to'liq qo'llanma. Noldan boshlab, professional darajagacha.

01 — ASOSLAR

Git nima?

Git — bu versiya boshqaruv tizimi (Version Control System). Oddiy qilib aytganda, Git sizning kodingizning har bir o'zgarishini eslab qoladi. Xuddi "Ctrl+Z" tugmasiga o'xshaydi, lekin minglab qadam orqaga qaytish imkonini beradi.

🎮 Hayotiy misol

Tasavvur qiling: siz katta referat yozyapsiz. Har safar o'zgartirish kiritganingizda "referat_v1.docx", "referat_v2.docx", "referat_final.docx", "referat_final_oxirgi.docx" deb saqlaysiz. Git aynan shu muammoni hal qiladi — u har bir o'zgarishni avtomatik eslab qoladi va siz istalgan vaqtda oldingi versiyaga qaytishingiz mumkin.

Git nima uchun kerak?

Tarixni saqlash — har bir o'zgarish saqlanadi, kim, qachon, nima o'zgartirganini bilish mumkin.

Jamoaviy ishlash — bir nechta dasturchi bir loyihada parallel ishlashi mumkin, bir-birining kodiga halaqit bermasdan.

Xavfsizlik — xato bo'lsa, oldingi holatga qaytish oson.

Eksperimental ishlash — yangi g'oyalarni sinab ko'rish uchun alohida "shoxcha" (branch) ochib, asosiy kodga tegmasdan ishlash mumkin.

💡

Eslab qoling: Git — bu dastur, u sizning kompyuteringizda o'rnatiladi va ishlaydi. Internet kerak emas. GitHub esa — bu onlayn platforma.

02 — PLATFORMA

GitHub nima?

GitHub — bu Git repositorylarini (loyiha papkalarini) internetda saqlash uchun platforma. U Git bilan ishlaydi, lekin Git emas. GitHub kodingizni bulutda saqlaydi va jamoa bilan birga ishlash imkonini beradi.

📱 Git vs GitHub — farqi

Git = Sizning telefoningizdagi kamera. U rasmlarni oladi (o'zgarishlarni saqlaydi).

GitHub = Google Photos. U rasmlarni bulutda saqlaydi va boshqalar bilan ulashadi.

Siz Git'siz GitHub'ni ishlata olmaysiz, lekin Git'ni GitHub'siz ishlatishingiz mumkin.

GitHub nima beradi?

Markaziy saqlash — barcha jamoa a'zolari bir joydan kod oladi va yuklaydi.

Pull Request — kodingizni tekshirish uchun so'rov yuborasiz, boshqalar ko'rib chiqadi.

Issues — vazifalarni yozish, xatolarni qayd qilish mumkin.

Actions — avtomatik test va deploy qilish mumkin.

03 — SOZLASH

Git o'rnatish va sozlash

Windows uchun

git-scm.com saytidan yuklab oling va o'rnating. O'rnatish jarayonida barcha standart sozlamalarni qoldiring.

Mac uchun

terminal 
brew install git

Linux (Ubuntu) uchun

terminal 
sudo apt install git

Birinchi sozlash (MAJBURIY)

Git o'rnatilgandan keyin, o'zingizni tanishtirishingiz kerak. Bu ma'lumotlar har bir commit'da ko'rinadi:

terminal 
# Ismingizni kiriting
git config --global user.name "Ismingiz Familiyangiz"

# Email manzilingizni kiriting (GitHub'dagi email bilan bir xil bo'lsin)
git config --global user.email "email@example.com"

# Tekshirish
git config --list
⚠️

Muhim: user.email — GitHub akkauntingizdagi email bilan bir xil bo'lishi kerak. Aks holda, commitlar sizning profilingizga bog'lanmaydi.

04 — REPOSITORY

Repository (Repo) yaratish

Repository — bu loyihangizning barcha fayllari va Git tarixi saqlanadigan papka. Har bir loyiha uchun bitta repo bo'ladi.

GitHub'da yangi repo yaratish

1

GitHub.com'ga kiring

O'z akkauntingiz bilan login qiling. Agar akkauntingiz bo'lmasa, ro'yxatdan o'ting.

2

"New repository" tugmasini bosing

Yuqori o'ng burchakdagi "+" tugmasi → "New repository".

3

Repo nomini kiriting

Masalan: my-awesome-project. Bo'sh joy ishlatmang, o'rniga tire (-) yoki pastki chiziq (_) qo'ying.

4

Sozlamalar

"Public" yoki "Private" tanlang. "Add a README file" ni belgilang. Keyin "Create repository" tugmasini bosing.

Repo'ni kompyuterga klonlash

GitHub'da repo yaratilgandan so'ng, uni kompyuteringizga yuklab olishingiz kerak:

terminal 
# GitHub'dan loyihani yuklab olish
git clone https://github.com/USERNAME/REPO-NAME.git

# Loyiha papkasiga kirish
cd REPO-NAME
💡

Maslahat: USERNAME o'rniga GitHub foydalanuvchi nomingizni, REPO-NAME o'rniga repo nomini yozing. Bu havolani GitHub repo sahifasidagi yashil "Code" tugmasidan nusxalashingiz mumkin.

05 — BRANCH

Branch (Shoxcha) tushunchasi

Branch — bu loyihaning alohida nusxasi. Asosiy kodga tegmasdan o'z ishingizni qilishingiz mumkin. Tayyor bo'lganda, asosiy kodga qo'shiladi.

🌳 Hayotiy misol

Tasavvur qiling: daraxt. Tanasi — bu main branch (asosiy kod). Har bir shox — alohida branch. Har bir dasturchi o'z shoxida ishlaydi, va tayyor bo'lgandan keyin, meva (kod) asosiy tanaga qo'shiladi.

Branch qoidalari (bizning loyiha uchun)

Har bir jamoa a'zosi o'z nomida branch ochadi. Branch nomi quyidagi formatda bo'ladi:

format 
# Branch nomlash formati:
feature/ism-vazifa

# Misollar:
feature/ali-header
feature/bobur-footer
feature/sardor-login
feature/dilshod-database
feature/jasur-homepage

07 — BUYRUQLAR

Asosiy Git buyruqlari

git init — Yangi repo yaratish

Bo'sh papkani Git repository'ga aylantiradi:

terminal 
# Yangi papka yarating va ichiga kiring
mkdir my-project
cd my-project

# Git ni ishga tushiring
git init

git status — Holatni tekshirish

Qaysi fayllar o'zgargan, qaysilari tayyor — hammasini ko'rsatadi:

terminal 
git status

# Natija misoli:
# On branch main
# Changes not staged for commit:
#   modified:   index.html
# Untracked files:
#   style.css
💡

Maslahat: git status ni tez-tez ishlating! Bu eng ko'p ishlatiladigan buyruq. Har qanday amaldan oldin va keyin ishlatib turing.

git add — Fayllarni tayyorlash (Staging)

O'zgargan fayllarni commit'ga tayyorlaydi:

terminal 
# Bitta faylni qo'shish
git add index.html

# Bir nechta faylni qo'shish
git add index.html style.css script.js

# BARCHA o'zgargan fayllarni qo'shish
git add .

# Bitta papkadagi barcha fayllarni qo'shish
git add src/

git commit — O'zgarishlarni saqlash

Tayyorlangan fayllarni Git tarixiga saqlaydi. Har bir commit — loyiha tarixidagi bir nuqta:

terminal 
# Commit yaratish (xabar bilan)
git commit -m "Header qismini yaratdim"

# Yaxshi commit xabarlari misollari:
git commit -m "Login sahifasi formasi qo'shildi"
git commit -m "Footer dizayni tuzatildi"
git commit -m "API bilan bog'lanish qo'shildi"
⚠️

Qoida: Commit xabari qisqa va tushunarli bo'lsin. Nima qilganingizni yozing. "fix" yoki "update" deb yozmang — bu hech narsani anglatmaydi!

git log — Tarixni ko'rish

terminal 
# To'liq tarix
git log

# Qisqa ko'rinish (bir qatorda)
git log --oneline

# Chiroyli grafik ko'rinish
git log --oneline --graph --all

git diff — O'zgarishlarni ko'rish

terminal 
# Hali add qilinmagan o'zgarishlar
git diff

# Add qilingan (staged) o'zgarishlar
git diff --staged

Umumiy jarayon: add → commit

1 Kod yozish
→
2 git add .
→
3 git commit -m "xabar"
08 — BRANCHLAR

Branch buyruqlari

Branchlar bilan ishlash

terminal 
# Barcha branchlarni ko'rish
git branch

# Yangi branch yaratish
git branch feature/ali-header

# Boshqa branchga o'tish
git checkout feature/ali-header

# Yangi branch yaratish VA o'tish (bir buyruqda)
git checkout -b feature/ali-header

# Zamonaviy variant (yangi usul)
git switch feature/ali-header
git switch -c feature/ali-header  # yaratish + o'tish

# Branch o'chirish (faqat merge qilingandan keyin)
git branch -d feature/ali-header

# Remote branchlar bilan birga ko'rish
git branch -a

Merge — Branchlarni birlashtirish

Biror branch'dagi ish tayyor bo'lganda, uni main branch'ga qo'shish kerak:

terminal 
# Avval main branchga o'ting
git checkout main

# So'nggi o'zgarishlarni GitHub'dan oling
git pull origin main

# Branch'ni main'ga qo'shing
git merge feature/ali-header

# Natijani GitHub'ga yuboring
git push origin main
🚫

Diqqat: main branch'ga to'g'ridan-to'g'ri kod yozmang! Har doim alohida branch'da ishlang va Pull Request orqali qo'shing.

09 — REMOTE

Remote (GitHub) buyruqlari

Remote — bu loyihaning GitHub'dagi nusxasi. origin — bu remote'ning standart nomi.

terminal 
# Remote'larni ko'rish
git remote -v

# GitHub'dan so'nggi o'zgarishlarni olish
git pull origin main

# O'z branch'ingizni GitHub'ga yuklash
git push origin feature/ali-header

# Birinchi marta push qilayotganda (branch'ni bog'lash)
git push -u origin feature/ali-header
# -u dan keyin oddiy "git push" yetarli

# GitHub'dagi barcha branch'larni yangilash
git fetch --all

# Boshqa odamning branch'ini olish
git fetch origin
git checkout feature/bobur-footer

Push va Pull — farqi

📤 git push — Yuklash

Sizning kompyuteringizdagi o'zgarishlarni GitHub'ga yuboradi. Xuddi faylni Google Drive'ga yuklash kabi.

📥 git pull — Yuklab olish

GitHub'dagi so'nggi o'zgarishlarni kompyuteringizga yuklab oladi. Boshqalar qilgan o'zgarishlarni olish uchun ishlatiladi.

10 — ISH JARAYONI

Har bir dasturchi uchun ish jarayoni

Quyida har bir jamoa a'zosi har kuni bajarishi kerak bo'lgan buyruqlar ketma-ketligi:

🟢 Ishni boshlash (har kuni)

har kuni 
# 1. Main'dagi so'nggi o'zgarishlarni oling
git checkout main
git pull origin main

# 2. O'z branchingizga qayting
git checkout feature/ali-header

# 3. Main'dagi yangilanishlarni o'z branchingizga qo'shing
git merge main

# 4. Endi ishlashni boshlang!

🔵 Ishni saqlash (kun davomida)

kun davomida 
# Holatni tekshiring
git status

# O'zgarishlarni tayyorlang
git add .

# Commit qiling
git commit -m "Navbar responsiv dizayn qo'shildi"

# GitHub'ga yuboring
git push origin feature/ali-header

🟣 Ish tugaganda (Pull Request)

ish tugaganda 
# Oxirgi marta hamma narsani push qiling
git add .
git commit -m "Header qismi tayyor"
git push origin feature/ali-header

11 — PULL REQUEST

Pull Request (PR) yaratish

Pull Request — bu "Mening kodimni ko'rib chiqing va main'ga qo'shing" degan so'rov. Bu jamoaviy ishlashning eng muhim qismi.

1

GitHub.com'ga kiring

Repo sahifasiga o'ting. Siz push qilganingizdan keyin, sariq banner paydo bo'ladi: "Compare & pull request" — shu tugmani bosing.

2

PR ma'lumotlarini to'ldiring

Title: Qisqa sarlavha. Masalan: "Header komponenti tayyor".

Description: Nima qilganingizni batafsil yozing. Qanday sahifalar qo'shildi, qanday funksiyalar ishlaydi.

3

Reviewer tayinlang

O'ng tomonda "Reviewers" bo'limida loyiha egasini (sizni) tanlang.

4

"Create Pull Request" tugmasini bosing

PR yaratildi! Endi loyiha egasi tekshiradi va merge qiladi.

Loyiha egasi: PR ni tekshirish va merge qilish

1

PR ni ochib, "Files changed" tabini ko'ring

Barcha o'zgarishlar yashil (qo'shilgan) va qizil (o'chirilgan) rangda ko'rsatiladi.

2

Kodni tekshiring

Xato bo'lsa — izoh yozing. Yaxshi bo'lsa — "Approve" qiling.

3

"Merge pull request" tugmasini bosing

Kod main branch'ga qo'shildi! Endi "Delete branch" tugmasini bosib, eski branch'ni o'chiring.

12 — KONFLIKTLAR

Merge Conflict — nima va qanday hal qilish?

Conflict — ikki kishi bir xil faylning bir xil qatorini o'zgartirganda yuzaga keladi. Git qaysi o'zgarishni saqlashni bilmaydi va sizdan so'raydi.

🤝 Hayotiy misol

Ali va Bobur ikkalasi ham index.html faylining 10-qatorini o'zgartirishdi. Ali sarlavhani "Salom" deb yozdi, Bobur esa "Xush kelibsiz" deb yozdi. Git qaysi birini saqlashni bilmaydi — bu conflict.

Conflict qanday ko'rinadi?

conflict misoli 
<<<<<<< HEAD
<h1>Salom Dunyo</h1>
=======
<h1>Xush kelibsiz</h1>
>>>>>>> feature/bobur-footer

Conflict'ni hal qilish

terminal 
# 1. Faylni oching va <<<, ===, >>> belgilarini o'chiring
# 2. Qaysi kodni saqlashni hal qiling
# 3. Faylni saqlang

# 4. O'zgarishlarni staging'ga qo'shing
git add index.html

# 5. Conflict hal qilinganini commit qiling
git commit -m "Merge conflict hal qilindi"
💡

Maslahat: Conflict'lardan qochish uchun — har kuni git pull origin main qiling va main'dagi yangilanishlarni o'z branchingizga merge qilib turing. Jamoa a'zolari bir xil faylda ishlamaslikka harakat qilsin.

13 — QOIDALAR

Jamoa qoidalari

✅ Har doim qiling

• Har kuni ishdan oldin git pull origin main qiling

• Commit xabarlarini tushunarli yozing

• O'z branchingizda ishlang, main'ga to'g'ridan-to'g'ri yozmang

• Tez-tez commit qiling (har 1-2 soatda, yoki har bir funksiya tayyor bo'lganda)

• Push qilishdan oldin git status va git diff bilan tekshiring

• Pull Request ochganingizda nima qilganingizni batafsil yozing

❌ Hech qachon qilmang

• main branch'ga to'g'ridan-to'g'ri push qilmang

• git push --force ishlatmang (agar bilmasangiz)

• Parollar, API kalitlar, va maxfiy ma'lumotlarni commit qilmang

• Katta fayllarni (video, zip, image) repo'ga qo'shmang

• node_modules papkasini commit qilmang — .gitignore ga qo'shing

.gitignore fayli

Ba'zi fayllarni Git kuzatmasligi kerak. Buning uchun .gitignore fayli yaratiladi:

.gitignore 
# Dependencies
node_modules/
vendor/

# Environment fayllar (maxfiy ma'lumotlar)
.env
.env.local

# IDE sozlamalari
.vscode/
.idea/

# Build fayllar
dist/
build/

# OS fayllari
.DS_Store
Thumbs.db
14 — YORDAM

Tez-tez uchraydigan xatolar va yechimlari

"Xato branch'da ishlayapman!"

terminal 
# Agar commit qilmagan bo'lsangiz:
git stash                           # O'zgarishlarni vaqtincha saqlash
git checkout feature/ali-header    # Kerakli branchga o'tish
git stash pop                       # O'zgarishlarni qaytarish

"Commit xabarini xato yozdim!"

terminal 
# Oxirgi commit xabarini o'zgartirish
git commit --amend -m "Yangi to'g'ri xabar"

"Faylni commit'dan chiqarish kerak!"

terminal 
# Staging'dan chiqarish (fayl o'zgarishi saqlanadi)
git reset HEAD fayl-nomi.txt

# Oxirgi commit'ni bekor qilish (o'zgarishlar saqlanadi)
git reset --soft HEAD~1

"Fayl o'zgarishini bekor qilish kerak!"

terminal 
# Bitta faylni oxirgi commit holatiga qaytarish
git checkout -- fayl-nomi.txt

# BARCHA o'zgarishlarni bekor qilish (EHTIYOT BO'LING!)
git checkout -- .

"Push qilolmayapman!"

terminal 
# Avval pull qiling, keyin push
git pull origin feature/ali-header
git push origin feature/ali-header
